The user begins by logging into the Orion Shell application using Google OAuth 2.0 authentication.
After successful authentication, a JWT token is generated by the Auth service and securely stored for subsequent API communication.



The Shell now acts as the container for independently deployed microfrontend modules.

Each feature module is an independently deployed microfrontend.
As shown in the network panel, different remoteEntry files are being dynamically loaded from separate deployments.

This demonstrates runtime module federation — where the Shell consumes remote applications without rebuilding the entire system.


When navigating to the Billing module, the request is sent to a unified GraphQL Gateway endpoint.


The Gateway parses the query, forwards billing-related fields to the Billing microservice, which then retrieves transactional data from Neon PostgreSQL.


The response is then composed and returned as a single structured result to the frontend.

Similarly, when accessing the Compliance module, the request flows through the same Gateway layer.

The Gateway delegates compliance-related queries to the Compliance microservice, which independently interacts with the database layer.

This ensures strict domain isolation while maintaining a unified API contract.

The Analytics module is another independently deployed microfrontend with its own backend service.


Even though these modules operate independently, the client interacts with a single GraphQL endpoint — while the Gateway intelligently orchestrates distributed service calls.

This system demonstrates a fully distributed, federated microservices architecture — with independent frontend modules, domain-isolated backend services, and unified API orchestration.
